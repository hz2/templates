# typst-template

A modular Typst paper/notes template with two diagram workflows: the same
Ipe pipeline as `latex-template`, and native `cetz` (Typst's TikZ-equivalent).

Two entry points share `template/`:

- `main.typ` -- a paper: title, abstract, outline, content split across
  `sections/*.typ`, bibliography.
- `notes.typ` -- running notes: title, outline, bibliography, but content is
  written directly inline as you go (no abstract, no splitting into section
  files).

## CI

`.github/workflows/build.yml` builds both `main.typ` and `notes.typ` (via
`nix develop`) on every push/PR and uploads the resulting PDFs as workflow
artifacts -- a quick way to catch a broken build without compiling locally.

## Setup

```
nix develop
```

gives you `typst`, `typstyle`, `ipe`, `ipetoipe`, `iperender`, and
`pdftoppm` in `$PATH`.

The theorem boxes (`@preview/ctheorems`) and the cetz diagram package
(`@preview/cetz`) are fetched from the Typst package registry on first
`typst compile` -- that first run needs network access; after that they're
cached locally and builds work offline.

## Building

```
make build       # export figures, then compile main.typ -> build/main.pdf
make notes       # export figures, then compile notes.typ -> build/notes.pdf
make watch       # typst watch main.typ, rebuilds on save
make watch-notes # typst watch notes.typ, rebuilds on save
make figures     # (re)export figures/ipe/*.ipe -> figures/svg, figures/png
make clean
```

## Layout

```
main.typ / notes.typ    entry points
template/                 modular styling, split by concern, imported with
                            root-relative paths (#import "/template/...")
  colors.typ               palette shared with figures/style.isy
  layout.typ                 page/heading setup, applied via #show: layout
  theorems.typ                 ctheorems-based boxes: thm, definition,
                                  example, remark, model, lemma, proof
  macros.typ                    fig() helper for Ipe-exported images, code()
  math-macros.typ                 optional domain notation pack, opt in
sections/                one file per section, #include'd from main.typ --
                            each section imports what it needs from
                            template/ itself (#include doesn't share scope)
references.bib           bibliography, read natively via #bibliography()
figures/
  ipe/                    Ipe diagram sources, edit these (plain XML)
  style.isy                shared Ipe palette
  svg/, png/                generated by `make figures`, not committed
  cetz/                     native cetz diagram sources (committed -- it's
                              code, not a generated export)
scripts/export-figures.sh
```

## Adding a diagram: two ways

**Ipe** (same workflow as `latex-template`, same `ipe-diagrams` Claude Code
skill): author `figures/ipe/*.ipe` as XML, `iperender -svg` to export for
embedding and `iperender -png` to render a preview to actually look at, then
place it with the `fig()` helper from `template/macros.typ`:

```typst
#import "/template/macros.typ": fig
#fig(70%, "example", [caption])
```

**cetz** (native, code-driven, no external editor): write a function
returning `cetz.canvas(...)` in `figures/cetz/*.typ` (see
`figures/cetz/example.typ`), then render and review it directly --
Typst compiles straight to png, no separate rasterizer needed:

```sh
typst compile figures/cetz/example.typ /tmp/preview.png --format png
```

then look at `/tmp/preview.png`. Iterate the same way as the Ipe workflow:
edit, render, look, repeat, before wiring it into a section with `#figure()`.

Both example diagrams (the Ipe one and the cetz one) are wired into
`sections/01-introduction.typ` side by side, for reference.

Theorem-box colors and diagram colors share one palette: six named colors
defined in `template/colors.typ`, `figures/style.isy` / embedded in each
`.ipe` file, and `figures/cetz/example.typ` -- `light-blue`, `light-green`,
`light-orange`, `light-red`, `light-purple`, `light-teal`.
